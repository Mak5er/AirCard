# Aircard 使用說明與疑難排解

適用於此 repo 的 v1.2.4.114514 自訂版本。

## 更新卡片

1. 連接並解鎖 iPhone，確認 App 顯示裝置已連線。
2. 選取卡片與外觀；需要時設定文字顏色或顯示末四碼。「不變更」保留原值，「自訂」需填四位數字，「隱藏」清空 Wallet 的末四碼顯示欄位，不會變更實際付款卡號。
3. 按下更新後保持連線，等待最終成功或失敗訊息。資料庫更新包含準備、寫入前比對、寫入、讀回驗證，期間可能需要等待。
4. 修改文字顏色或顯示末四碼後，需重新啟動 iPhone 才能套用。只有更換外觀時，可先關閉並重新開啟 Wallet 查看。

## Wallet 空白或卡片暫時消失

修改卡號顏色後，Wallet 可能暫時不顯示卡片。依原作者說明（由使用者提供），可嘗試：

1. 先確認電腦端操作已結束；不要在後端仍執行時拔線或重新啟動手機。
2. 重新啟動 iPhone。
3. 開啟 Wallet；若仍空白，等待約一分鐘。
4. 從多工畫面關閉 Wallet，再重新開啟，確認卡片是否恢復。

這是處理 Wallet 顯示異常的方法，不代表每次資料庫或還原錯誤都能自動恢復。若仍空白，先停止重試，保留錯誤紀錄與復原檔供排查。

## `ExtractionRestoreError`、`AFC=8` 或 `file_not_found`

可能看到這類紀錄：

```text
準備資料庫：讀取主資料庫…
ExtractionRestoreError: prepare-main … passes23.sqlite：找不到檔案
（AFC=8，原因=file_not_found）
後端已結束（退出碼 1），本次更新未確認成功。
```

`AFC=8` 表示查詢的檔案不存在。在這個錯誤裡，查詢的是本輪產生的 `Media/airlift-recovered-…` 復原檔；不能只憑這行就判定原位置的 Wallet 資料庫或卡片資料已遺失。

「準備」階段也可能暫時搬移原始檔並嘗試還原，因此尚未套用新設定不代表手機完全沒有變動。舊版的「原始檔尚未還原」訊息也不能單獨證明檔案目前的位置或是否已成功寫回。

- 先停止重複按更新。連續重試不會證明先前已還原。
- 保留完整錯誤紀錄，包括時間、操作識別碼及每一次的復原檔路徑。早先失敗留下的復原檔也可能有用。
- 不要刪除、清理或用舊復原檔直接覆寫手機資料庫；舊副本可能與目前狀態不同。
- 確認後端已結束後，可依上面的 Wallet 空白處理步驟確認卡片顯示。
- 若仍未恢復，需先確認復原檔與目前資料庫狀態，再決定恢復方式。匯出資料庫可能涉及卡片與帳戶敏感資訊，應先取得同意並保存於指定的私人本機位置，不要公開上傳。

這個版本在讀不到主資料庫或無法確認還原時會中止，不會把主資料庫缺失當成可忽略的可選日誌檔。

## 進度停住或沒有訊息

舊版曾在資料庫寫入剛開始時提前算完該部分進度，含圖片的操作會長時間停在 30%。修正版會顯示實際步驟，並在後端持續執行但沒有新輸出時每約 15 秒補一則等待紀錄。

等待訊息只代表後端程序仍在執行，不保證裝置操作正在推進；不要把它當作成功。應以最後的完成或失敗紀錄為準，排查時請保留最後幾行與已等待的時間。

## `device_helper` 崩潰

曾確認一個原生裝置通知回呼在程序收尾時存取已釋放識別碼的問題，崩潰訊號為 `SIGTRAP`；此 repo 已修正回呼生命週期，並補上子命令、退出碼及訊號紀錄。

若仍出現崩潰，保留完整紀錄供排查。修正輔助程式的崩潰，不等於之前中斷的資料庫操作已恢復成功。
