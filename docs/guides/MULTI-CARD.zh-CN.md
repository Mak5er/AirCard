# 多卡操作与部分失败处理

[返回中文指南](README.zh-CN.md) · [English](MULTI-CARD.en.md) · [分阶段排障](TROUBLESHOOTING.zh-CN.md)

以下描述来自当前图形界面与后端代码，不代表所有 iPhone / iOS 组合均经过实测。第一次使用时，先用一张已确认对应的卡完成整个流程，再扩展到多张。

## 卡片列表保存了什么

AirCard 保存的是卡片的**内部标识**，不是卡号，也不是手机钱包的实时清单。程序启动时会读取 Mac 上的已保存记录；扫描找到新标识时将其追加并保存。

| 内容 | 关闭再打开 app 后 |
| --- | --- |
| 卡片标识与列表顺序 | 保存；旧版本保存的记录也可能被导入。 |
| 勾选状态 | 不保存；加载的卡片默认全部勾选。 |
| 分配的图片、图片路径、预览 | 不保存，需要重新分配。源文件也要继续保留在 Mac 上。 |
| 与某台 iPhone 的绑定 | 未按设备分组；换手机后不能把旧列表当成新手机的卡片。 |

界面的 **Card #1 / #2** 是列表序号，不是银行名称、付款卡号或可靠的 Wallet 排序。不要仅靠序号猜测对应关系。扫描时一次点选一张卡，观察新出现的记录；不能确认时，先停止刷入、重新核对。不要从他人的截图复制标识到 **Add Manually**。

代码将标识保存在 `UserDefaults` 和 `~/.aircard_cards.json`，并读取旧的 `~/.lumicards_cards.json`。这些文件不是原卡面的备份。清空后重新打开仍见旧条目时，也应考虑旧记录被再次导入的可能，不能据此认定手机重新扫描成功。

原始卡面会另外保存在这台 Mac 的 `~/Library/Application Support/AirCard/OriginalCardSkins`，使用受限的本地文件权限，并按 iPhone 和卡片分别保存。如果之后可能需要恢复，请保留这台 Mac 上的 AirCard 支持文件。带恢复功能的版本会在首次更改卡面前保存原图；旧版本或其他工具已经修改的卡片无法被安全识别或重建，当前文件可能已经是自定义卡面。AirCard 会在刷入前提醒；对于已知曾刷入但没有恢复点的卡片，不会将其误标为已有备份。

## 不同卡分别用不同图片

1. 确认连接区域显示目标 iPhone；先停止扫描，固定本次处理的列表。
2. 点击 **Deselect All**，然后逐张选择需要更换的目标卡。
3. 点击卡面或将图片拖到对应卡片上，分别分配图片。**分配图片会自动勾选该卡**，所以配图后再核对勾选状态。
4. 检查底部 `ready to flash` 数量与 **Flash Skins (N Cards)**。参与刷入的条件是：**已勾选，且有分配的图片路径**。
5. 确认源文件仍能正常打开，然后点击 **Flash Skins**。完成后逐张在 iPhone 中核对实际卡面。

例如：A 卡已勾选并配图、B 卡已勾选但没配图、C 卡有图但未勾选，本次只会处理 A。`ready to flash` 表示配置条件满足，不是已经验证图片有效或确认手机写入成功。

## 多张卡使用同一张图

勾选目标卡后点击 **Set Skin for All…** 选择图片。这里的 “All” 只指**当前勾选的卡**；未勾选的卡不会被配图，也不会清除它们以前分配的图片。

若希望全部卡使用同一张图，先 **Select All** 再 **Set Skin for All…**；若只想处理其中两张，先 **Deselect All** 再勾选两张。最后重新检查 `ready to flash` 数量。

## 容易混淆的按钮

| 操作 | 实际作用 |
| --- | --- |
| 取消勾选 / **Deselect All** | 从下一次刷入队列排除卡片；已分配图片留在当前会话。 |
| 卡面右上角 × / **Remove skin** | 清除 Mac 上该卡待应用的图片和路径；不向手机写入原图。 |
| **Restore Original** | 仅当这台 Mac 有完整恢复点时可用。确认后会写回保存的卡面并清理 Wallet 渲染缓存；之后请强制关闭 iPhone 上的 Wallet。 |
| 垃圾桶 / **Remove from list** | 删除并保存 Mac 上的列表记录；不删除手机中的支付卡。 |
| **Clear All**（Apple Wallet 页） | 清空并保存当前 Mac 卡片列表；不删除 Wallet 卡片、不清理手机缓存、不恢复卡面。需要刷新清单时先停止扫描，否则新日志仍可追加卡片。 |
| **Stop Scanning** | 终止找卡日志进程；不是停止刷入或撤销更改的按钮。 |

本表针对 **Apple Wallet** 页，不包含密码主题制作页面的同名清除按钮。

## 中途失败后怎么处理

刷入按列表中符合条件的卡逐张执行。**任一卡片的刷入进程启动失败或非零退出时，本次队列停止，后续卡不继续处理；之前的写入不会自动回滚。** 同一张失败卡内部也可能已有部分文件写入。

例如顺序为 A → B → C，A 成功而 B 失败：A 可能已经改变；B 的状态须检查；C 尚未处理。界面的整批失败提示不能解释成“全部未改”。

1. 在 **Log** 找到失败前最后的 `Flashing card [n/total]`、该卡的错误，以及此前各卡是否出现 `Successfully updated …`。不要只看进度百分比。
2. 按[排障手册](TROUBLESHOOTING.zh-CN.md)处理连接、图片或缓存问题，保留原始素材文件。
3. **Deselect All**，仅选择失败卡，重新确认配图并重试；不必把已经报告成功的卡全部再刷一次。
4. 该卡成功后，再选尚未处理的卡继续。原有图片分配在同一会话内仍保留；如果重启过 app，则需重新配图。
5. 关闭并重新打开 iPhone 上的 Wallet，逐张确认显示。仍未更新时可尝试重启手机，并记录结果；重启不保证恢复旧卡面。

后端会先尝试一次批量写入**一张卡的素材文件**，失败后逐文件重试；之后还要清理两类 Wallet 渲染缓存。恢复会写回首次受支持的卡面更改前保存的 PNG/PDF；恢复后本地快照仍会保留。恢复操作不是事务，途中仍可能失败。删除钱包里的银行卡不是这里的恢复步骤。
